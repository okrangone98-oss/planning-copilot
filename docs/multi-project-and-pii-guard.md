# 다중 사업 관리 보드 · 개인정보 마스킹 가드

한 브라우저에서 여러 정부·공모·자체 사업을 나눠 관리하고, 외부 AI로 보내기 전에 개인정보를 자동으로 가리는 모듈입니다.
두 기능 모두 브라우저 안에서만 동작하며, 새로 서버에 보관하는 데이터는 없습니다.

## 1. 사업 보드

### 화면

| 위치 | 하는 일 |
| --- | --- |
| 시작 화면 → `내 사업 N개` | 사업 카드 목록에서 바로 전환, `사업 관리`로 이동 |
| 사이드바 맨 위 `현재 사업` | 셀렉터로 즉시 전환, 상태·D-day·진행률 표시, `+ 새 사업` |
| 업무 홈 → `사업 관리` | 사업 카드(유형·상태·D-day·진행률·수정일), 새 사업 만들기, 복제·삭제, 현재 사업 정보 수정 |

### 사업 하나가 가지는 값

- 사업명, 유형(국고보조 / 시군역량 / 공모 / 자체 / 기타), 상태(11종), 마감일(D-day), 진행률, 생성·수정일
- 2026-11 확장: 사업 연도, 담당자, 운영 기간(시작·종료), 목표(최대 5), 출처·참고(최대 8)
- 상태 11종: 아이디어 · 기획 중 · 신청 완료 · 검토 중 · 확정 · 운영 준비 · 운영 중 · 정산·평가 · 완료 · 보류 · 취소.
  기존 저장 데이터의 `planning`·`submitted`·`running`·`done` id는 그대로 두었고, `running` 라벨만 "집행·정산"에서 "운영 중"으로 바뀌었습니다(값 손실 없음).
- 진행률은 자동 계산입니다. 사업계획서 40 · 예산 편성 25 · 정산 증빙 20 · 결과보고 15의 가중 평균이고, 화면의 `진행률 구성`에서 항목별 값을 볼 수 있습니다.
- D-day는 마감일이 지나면 `D+2`처럼 표시합니다(`D-DAY`, `마감일 없음` 포함).

### 저장 구조

| 데이터 | 저장 키 |
| --- | --- |
| 사업 목록·활성 사업 | `planningCopilotWorkspace` |
| 사업별 사업계획 입력값 | `planningCopilotProject:<projectId>` |
| 사업별 예산·정산 | `planningCopilotGrantPlan:<projectId>` |
| 사업별 양식 채우기 | `planningCopilotTemplateSession:<projectId>` |
| 사업별 운영 데이터(업무·회차·리비전·변경 이력) | `planningCopilotProjectWork:<projectId>` |

- 사업은 최대 20개까지 만들 수 있고, 마지막 남은 사업은 삭제되지 않습니다.
- 사업을 전환하면 네 가지 작업 데이터(사업계획·예산·양식·운영)가 그 사업의 것으로 함께 바뀝니다. 삭제는 확인 창을 거치고, 삭제한 사업의 데이터 키도 함께 지웁니다.
- 운영 데이터는 비어 있으면 저장 키를 만들지 않습니다. 사업을 복제하면 업무·회차는 새 id로 한 벌 더 만들어지고(멱등 키는 유지), 변경 이력은 원본 기록이라 복사하지 않습니다.
- 사례 모음·승인함·프로젝트 기억·모델 설정은 사업과 무관한 공용 자료로 남겨 둡니다.

### 기존 사용자 데이터 옮기기

예전 단일 키(`planningCopilotProject`, `planningCopilotGrantPlan`)에 작업이 있으면 첫 로드에서 첫 사업 슬롯으로 자동으로 옮깁니다.

- 옮긴 뒤에도 예전 키는 지우지 않습니다. 되돌릴 여지를 남기기 위해서입니다.
- 한 번 옮기면 `legacyMigrated` 표시를 남겨 다시 옮기지 않습니다.
- 사업이 하나뿐인 상태에서 사업별 키가 비어 있으면 예전 키를 한 번 더 읽어 복구합니다.

### 백업·복원

- `설정·연결 → 백업`의 백업 파일은 이제 **모든 사업**을 한 파일에 담습니다(`kind: "workspace"`, 사업별 작업 데이터 + 사례·승인함·기억).
- 파일 형식은 `version: 7`입니다. 사업별 항목에 `work`(업무·회차·리비전·변경 이력)가 함께 들어갑니다.
- 예전 백업(`version: 6` 이하, `work` 없음)과 단일 백업 파일(`project` + `grantPlan`)도 그대로 복원됩니다. 이때 업무·회차는 빈 상태로 시작합니다.
- 저장 형식(schemaVersion)이 2→3으로 올라갈 때 한 번만 안내합니다. 자동으로 파일을 내려받지는 않습니다(사용자 확인 없이 파일을 만들지 않음).
- 백업 파일에는 API 키·토큰류를 담지 않습니다. 저장된 값에 섞여 있어도 `stripSecrets`가 걷어냅니다.

## 2. 개인정보 가드

### 찾는 항목

| 종류 | 표시 | 비고 |
| --- | --- | --- |
| 주민등록번호 / 외국인등록번호 | `[주민번호_1]` | 검사번호까지 맞는 13자리만 인정, 뒷자리 5~8은 `외국인등록번호`로 표시 |
| 휴대폰·유선전화 | `[연락처_1]` | `010-1234-5678`, `01012345678`, `+82 10-…`, `02-…`, `033-…`, `070-…` |
| 이메일 | `[이메일_1]` | |
| 계좌번호 | `[계좌_1]` | 은행·계좌 표시가 앞에 있을 때만(오탐 방지) |
| 카드번호 | `[카드_1]` | Luhn 검사 통과 |
| 사업자등록번호 | `[사업자번호_1]` | 선택 사항(기본 OFF), 국세청 검사번호 통과 |
| 도로명·지번 주소 | `[주소_1]` | 지번은 시·군·구 표기가 앞에 있을 때만 |
| `성명:`·`담당자:`·`대표자:`·`예금주:` 뒤 이름 | `[성명_1]` | 콜론이 있을 때만, `없음`·`미정` 같은 상투어는 제외 |

- 같은 값은 같은 번호를 씁니다. `010-1234-5678`과 `01012345678`은 둘 다 `[연락처_1]`입니다.
- 이미 가린 텍스트에 다시 적용해도 더 바뀌지 않습니다(멱등).
- 날짜(`2026-11-15`), 금액(`50,000,000원`), 접수번호는 개인정보로 잡지 않습니다.

### 화면에서

- `공고 해석`, `외부 AI 질문`, `샘플 양식 채우기`에 **점검 배지**가 있고, 기본값은 `마스킹 후 보내기` 켜짐입니다.
- 배지에는 `연락처 2 · 이메일 1`처럼 종류별 건수가 뜨고, `탐지 목록 보기`로 가린 미리보기(`010****5678`)와 치환 토큰을 확인할 수 있습니다.
- 실제로 가려지는 곳: 무료 API 실행, AI 사무국 실행, 모델 테스트, 질문 복사, 양식 채우기 프롬프트 복사, AI 사무국의 GPT 질문 복사.
- 화면에 입력한 원문은 그대로 둡니다. 가린 텍스트는 밖으로 나가는 순간에만 만들어지고 저장되지 않습니다.
- 끄면 원문이 그대로 나가고, 배지에 경고가 남습니다. 끈 선택은 `planningCopilotPiiMask`에 기억합니다.
- `워크브레인 내보내기`는 문서 전체를 점검해 `개인정보 N건`을 보여 주고, `원클릭 마스킹`을 누르면 복사·내려받기·Notion 복사가 모두 가린 문서로 바뀝니다.

### 라이브러리

`src/lib/piiGuard.mjs`(+ `.d.mts`)는 브라우저와 node 테스트에서 함께 씁니다.

```js
import { scanPii, maskPii, maskRecord } from "./src/lib/piiGuard.mjs";

scanPii("연락처 010-1234-5678");     // { total, findings, counts, badgeText, … }
maskPii("연락처 010-1234-5678");     // text: "연락처 [연락처_1]", placeholders: […]
maskRecord({ memo: "010-1234-5678" }); // 외부 전송 페이로드(객체) 전체 점검
```
