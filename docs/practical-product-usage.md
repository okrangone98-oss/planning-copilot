# 실무 중심 Planning Copilot 사용 안내

## 지금 사용할 수 있는 업무

| 업무 영역 | 사용 목적 |
| --- | --- |
| 업무 홈 | AI 사무국 명령 실행, 로컬 하네스 기록 확인 |
| 프로젝트 | 질문 정리, 문제정의, 사업 논리와 실행계획 작성 |
| 자료·근거 | 공고 분석, 사례 정리, 프로젝트 기억 관리 |
| 산출물·검토 | 문서 초안, 시각자료, 승인함, 외부 AI 질문 준비 |
| 설정·연결 | 모델 설정, 프로젝트 링크, 백업 |

기존 20개 화면과 저장 데이터는 유지한다. 저빈도 도구는 하위 메뉴로 옮겼으며 기능 코드를 삭제하지 않았다.

## 권장 작업 순서

1. 프로젝트 정보를 입력하고 공고·사례·확인된 근거를 정리한다.
2. 업무 홈의 AI 사무국에 원하는 작업을 입력한다.
3. 작업 분해, 담당 역할, 역할별 템플릿 초안, 최종 보고서를 확인한다.
4. 사실·예산·일정을 검토하고 필요한 결과만 승인함과 프로젝트 기억에 저장한다.
5. 설정·연결의 백업에서 데이터를 내려받아 로컬의 보호된 폴더에 보관한다.

시뮬레이션은 API 키 없이 즉시 사용 가능하지만 실제 조사나 모델 추론을 수행하지 않는다. 역할별 초안은 Ollama 모드에서도 규칙 기반 템플릿이며, 실제 모델이 작성하는 부분은 통합 최종 보고서다. 여러 에이전트가 독립적으로 실행되는 구조는 아니다.

## 실제 로컬 모델 사용

설치된 Ollama 서버를 실행한 뒤 설정·연결 → 모델 설정에서 Ollama를 선택한다. 기본 주소는 `http://localhost:11434`이며 설치 모델 목록을 불러와 로컬 모델을 선택하고 연결을 시험한다. 서버 연결과 브라우저 접근 허용 설정이 필요하다.

Ollama는 localhost 서버에서도 클라우드 모델을 호출할 수 있다. 로컬 전용 운영은 서버 환경변수 `OLLAMA_NO_CLOUD=1`을 설정하고 Ollama를 다시 시작하는 것이 권장된다. 공식 안내: [Ollama FAQ](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features).

앱은 loopback 주소만 허용하고 클라우드 모델 이름·메타데이터를 차단한다. 모델 정보 확인 요청에는 모델명만 보내고, 로컬 모델 확인 후에 프로젝트 자료를 포함한 생성 요청을 보낸다. 연결 실패·모델 확인 실패·시간 초과는 오류로 표시하며 템플릿 성공으로 숨기지 않는다. 신뢰할 수 있는 로컬 Ollama 설치를 사용해야 한다.

## 데이터와 안전 경계

- 브라우저 앱 데이터는 해당 브라우저와 주소의 localStorage에 저장된다. 자동으로 GitHub나 Drive에 저장되지 않는다. 브라우저 데이터 삭제와 주소 변경에 대비해 백업한다.
- 모델 입력은 현재 프로젝트의 허용된 항목과 매칭된 저장 자료 최대 3건이다. 긴 입력은 항목별 발췌로 제한된다. 프로젝트 전체 백업이나 승인함 전체를 모델에 전달하지 않는다.
- 기존 브라우저 모델 설정에 저장된 클라우드 API 키 필드는 제거한다. 프로젝트·기억·승인 데이터는 이 정리 대상이 아니다.
- 모델의 근거 표시는 검토를 돕기 위한 것이며 사실 검증을 보장하지 않는다. 최신 공고와 수치는 원문을 확인한다.
- 자동 이메일 발송·공문 제출·외부 게시는 없다. 프로젝트 링크는 URL 보관과 열기이며 API 동기화가 아니다.
- Google Workspace 읽기 실행기는 별도 OAuth 설정이 필요하다. 이번 검증에서 실제 계정 접근이나 원본 변경은 수행하지 않았다.

- `npm run office:test`: 68개 통과, 실패 0개.
- `npm run check`: TypeScript, Vite 빌드, 기존 스크립트 구문 검사 통과. 별도 lint 스크립트는 없다.
- 격리된 Playwright 브라우저에서 1440×1000 / 390×844 화면별 20개 메뉴 접근, 템플릿 실행, 설정 정리, 승인·기억 저장과 재로드를 확인했다.
- 모의 Ollama 응답으로 모델 목록, 메타데이터 검사, 최종 보고 생성, 실패 표시, 원격 모델 차단을 확인했다. 브라우저 오류와 가로 넘침은 없었다.
- 실제 Ollama 서버는 실행되지 않아 실제 모델 추론과 결과 품질은 미검증이다.
- 기존 PDF·Mermaid 관련 큰 번들 경고는 남아 있다. 빌드 오류는 아니다.

## 배포와 로컬 실행의 차이

배포 주소는 `https://okrangone98-oss.github.io/planning-copilot/`이다. 사용자 승인 후 기능 브랜치를 푸시하고 PR을 `master`에 병합하면 기존 GitHub Pages 워크플로우가 배포한다. 배포 완료 여부는 Actions 실행 결과와 공개 화면에서 별도로 확인한다.

배포 사이트와 로컬 개발 주소는 서로 다른 localStorage를 사용한다. 로컬 데이터를 옮기려면 로컬 앱에서 백업을 내려받고 배포 사이트에서 가져온다. 배포해도 개인 보고서와 OAuth 파일은 업로드하지 않는다.

공개 사이트에서도 템플릿은 바로 사용할 수 있다. Ollama는 사용자의 컴퓨터에서 별도로 실행해야 하며 서버의 허용 Origin과 브라우저의 로컬 네트워크 접근 정책에 따라 연결이 제한될 수 있다. 허용 범위를 무제한으로 열지 말고 필요한 주소만 지정한다. 공개 사이트와 실제 로컬 모델 간 연결은 이번 모의 API 검증만으로 보장되지 않는다.
