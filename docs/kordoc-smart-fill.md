# kordoc 양식 규격 채우기 · 자유 텍스트 자동 배치

`샘플 양식 채우기` 화면을 **kordoc(chrisryugj/kordoc)의 양식 규격**에 맞춰 넓힌 2단계 작업입니다.
양식을 처음 보는 사람도 ① 각 칸이 무엇을 받는 자리인지 바로 알고, ② 카톡·메모·회의록에서 복사한 글을
통째로 붙여넣으면 알맞은 칸으로 나뉘어 들어가고, ③ 그 값이 실제 한글(.hwpx) 양식에 kordoc `fill`/`patch`로
정확히 들어가도록 연결합니다.

- 대상 화면: `문서·예산 실무 → 샘플 양식 채우기` (메뉴는 그대로 10개)
- 브라우저 단독으로 되는 일과 안 되는 일을 섞지 않습니다. 파일 읽기·분류·미리보기는 브라우저 안에서,
  실제 .hwpx 쓰기는 로컬 kordoc(명령 또는 브릿지)이 맡습니다.

## 1) kordoc 양식 규격을 그대로 옮긴 인식기

`src/lib/kordocFormSpec.mjs` 는 kordoc `src/form/recognize.ts`·`match.ts`·`filler-hwpx.ts` 의 규칙을
브라우저에서 쓸 수 있게 옮긴 구현입니다.

| kordoc | 이 앱 | 하는 일 |
| --- | --- | --- |
| `isLabelCell` | `isFormLabelCell` | 라벨 칸 판정(키워드 + 짧은 한글 + `라벨:` + 영문 관행) |
| `isBlankValueCell` | `isBlankValueCell` · `isDatePlaceholderCell` | 빈 값·자리표시·날짜 자리(`년 월 ~ 년 월`) 구분 |
| `isSubLabelBeside` | `isSubLabelBeside` | 행 머리 옆 하위 라벨을 값 자리로 오인하지 않기 |
| `columnHeaderMap` | `isColumnHeaderRow` | 열 머리 행(라벨이 위, 값이 아래) 판정 |
| `normalizeLabel` | `normalizeFormLabel` | 콜론·공백·괄호를 걷어 비교 |
| `findMatchingKey` | `findMatchingFieldKey` | 정확 일치 → 접두사 60% / 역방향 75% |
| `inferFieldType` | `fieldTypeOf` | date·amount·phone·email·idnum·checkbox 추론 |
| `scanInlineSegments` | `scanInlineFieldSegments` | 한 줄에 여러 라벨(“사업명: … / 기간: …”) 분해 |

### 문서 구조에서 읽는 것

- **제목 계층**: `Ⅰ.`·`1.`·`가.`·`①`·`【…】` 와 HWPX 표 안의 **장 띠**(`Ⅰ | | 사업 개요`)를 제목으로 읽습니다.
- **1×1 틀**: 표지·요약 상자로 쓰인 한 칸짜리 표는 표가 아니라 문단·제목으로 돌려줍니다(빈 칸 수가 부풀지 않음).
- **칸 좌표·병합**: HWPX의 `cellAddr`·`cellSpan` 을 읽어 병합 칸 글자를 제자리에 놓고, 병합이 있는 표에만
  `spans`(`[rowSpan, colSpan]`)를 담습니다.
- **`라벨 | 빈칸` 쌍**: “구분 | 내용” 같은 표는 행마다 라벨·값으로 읽고, 라벨 오른쪽(또는 열 머리 아래) 칸을
  채울 자리로 잡습니다. 열 머리 표는 열 이름이 kordoc 채우기 키가 됩니다.
- **글자로 남은 자리 표시**: `{{사업명}}`, `[입력]`, `[사업명]`, `___`, `○○`, `(   )`, `년 월 ~ 년 월` 도 값 자리로 읽습니다.
- **작성 힌트**: 같은 구역의 `※`·`(작성 요령)` 문장을 그 구역 칸의 힌트로 붙입니다. 화면 2번의
  “이 양식의 칸 N개 — 무엇을 넣는 자리인지” 접이식 목록에서 칸 이름·받는 값 종류·구역·힌트·이미 적힌 값을 함께 보여 줍니다.

### 연습 양식(실제 .hwpx)

`공고 파일이 아직 없어도` 버튼 한 번(`올릴 파일이 없으면 연습 양식 불러오기`)으로 기관 표준 사업계획서
연습 양식을 읽습니다.

- `public/practice/plan-practice-form.hwpx` — kordoc `generate --preset 계획서` 로 만든 **실제 한글 문서**(7장 25칸).
- `public/practice/plan-practice-form.md` — 같은 내용의 원문. 파일을 못 불러오면 이 글로 구조를 읽습니다(대체 경로).
- 다시 만들 때: `node scripts/make-practice-template.mjs` (양식 원문은 `src/lib/practiceTemplate.mjs` 한 곳에만 있음)

## 2) 자유 텍스트 자동 분류·칸 배치

`src/lib/smartTextMapper.mjs` — 붙여넣은 글을 칸으로 나눕니다. **2단계**로 동작합니다.

1. **AI 경로(무료 키가 설정된 경우)**: 칸 번호·이름·구역·힌트·받는 값 종류와 원문을 보내고,
   `{"assignments":[{"fieldId","text","reason"}],"unassigned":[…]}` JSON 만 받습니다. 코드블록·머리말이 섞여도
   JSON 을 찾아내고, 깨졌거나 칸 번호가 없으면 **규칙 결과로 넘어갑니다**(폴백 계약). AI 가 비운 칸은 규칙이 마저 채웁니다.
2. **규칙 경로(키가 없어도 즉시)**
   - 줄 하나가 생각 하나: `라벨: 값` 줄은 라벨째, `○·-·1.` 목록은 항목째, 나머지는 문장 단위로 나눕니다.
   - 라벨 유사도: 동의어 사전(사업명·수행기관·기간·사업비·현황·문제점·목표·대상·추진내용·일정·비목·성과…)으로
     칸 이름과 낱말을 맞추고, 문자 2-gram 유사도를 함께 봅니다.
   - 값 모양 패턴: 날짜(`2027년 3월 ~ 11월`), 금액(`4,800만원`), 인원(`20명`), 기관명(`…센터·…군·…재단`),
     전화·메일, 문제 어미(`부족·감소·떠나·한계`)를 칸 성격과 대조합니다.
   - 라벨이 같은 줄은 점수 1.0, 나머지는 0.42 이상만 받아들입니다.

### 미리보기 → 체크 → 적용

- 행마다 **어느 칸에 / 어떤 글을 / 왜**(라벨이 같은 줄·낱말 겹침·값 모양·같은 구역) 넣는지 보여 줍니다.
- 칸에 **이미 글이 있으면 기본은 “유지”**(체크 해제 상태)이고, `지금 적힌 글: …` 을 함께 보여 줍니다.
  체크해야만 바뀝니다. 원본 칸 글은 사용자가 확인하기 전에 지우지 않습니다(`applyFieldValues`, `force` 옵션).
- **배치하지 못한 글**은 접어서 보여 주고, `남은 글을 초안 조립으로 보내기`로 초안 화면에 넘길 수 있습니다.
- “모두 선택/해제”, “선택한 N칸 채우기”: 체크한 칸만 값으로 들어가고, 표 미리보기·칸 목록·채우기 데이터가 같이 갱신됩니다.

## 3) kordoc 채우기 데이터 · 실제 문서 채우기

`buildKordocFillValues` 는 채운 값을 kordoc `fill -j` 가 그대로 먹는 JSON 으로 만듭니다.

- 키는 칸 라벨 글자(콜론·공백 제거) — kordoc 이 같은 규칙으로 정규화하므로 그대로 맞습니다.
- 같은 라벨이 여러 칸이면(예: 열 머리 “기간” 아래 여러 행) **등장 순서 배열**로 넣고, 화면에 순서 확인 경고를 띄웁니다.
- 패널에서 `채움값 JSON 복사`·`채움값.json 내려받기`·`fill 명령 복사`·`patch 명령 복사`를 제공합니다.

```
npx -y kordoc@4.24.80 fill "양식.hwpx" -j "양식-채움값.json" -o "양식-채움.hwpx"   # 원본 서식 유지, 빈 칸만 채움
npx -y kordoc@4.24.80 patch "양식.hwpx" "양식-채운문서.md" -o "양식-반영.hwpx"    # 만든 채운 문서를 서식에 반영
```

### 로컬 브릿지

```bash
node scripts/kordoc-bridge.mjs            # http://127.0.0.1:8787/kordoc (127.0.0.1 에만 열림)
PORT=8790 node scripts/kordoc-bridge.mjs  # 포트 바꾸기
```

브릿지는 `{ engine:"kordoc", mode:"fill"|"patch", fileName, templateBase64, values|markdown, outputName }` 를 받아
임시 폴더에서 kordoc 을 실행하고 `{ ok, fileName, base64 }` 로 돌려줍니다(`generate` 요청도 그대로 받습니다).

- 셸을 거치지 않고 `execFile` 로 실행하고 값은 `-j` 파일로만 넘깁니다.
- 임시 폴더는 응답 뒤 지우고, 값·문서 내용은 로그에 남기지 않습니다.
- 앱의 `내 컴퓨터 브릿지로 바로 채우기`에 주소를 넣으면 채운 `.hwpx`를 바로 내려받습니다.

## 한계 (화면에도 적어 둡니다)

- **fill/patch 는 .hwpx·.hwp 양식만** 됩니다. PDF·DOCX로 올린 양식은 구조 읽기·자유 텍스트 배치까지 되고,
  실제 채우기는 kordoc `generate`/`patch` 경로(결과 .md → .hwpx)로 이어집니다.
- 구형 `.hwp`(바이너리)는 브라우저에서 구조를 읽지 못합니다(한글에서 HWPX로 저장 안내).
- 병합 칸은 첫 칸에만 글자가 담기므로 빈칸 수가 실제보다 많게 보일 수 있습니다(이제 `spans` 로 병합을 인식합니다).
- AI 경로는 사용자가 고른 무료 모델 설정에 따르며, 키가 없으면 규칙 경로만 씁니다. 채운 값은 외부로 나가지 않습니다.

## 검증

```
npm test           # 250개 (기존 225 + kordoc 규격·자유 텍스트·브릿지 25)
npx tsc --noEmit
NODE_OPTIONS=--max-old-space-size=1024 npm run build
npm run check
```

헤드리스 Chromium(1440×1000 / 390×844)에서 확인한 흐름과 화면은
`downloads/planning-copilot-kordoc-fill/` 에 있습니다.

1. 연습 양식 불러오기 → 섹션 7개·표 7개·칸 25개, 힌트 표시
2. 메모 붙여넣기 → 23칸 자동 배치(라벨 일치 21칸 + 규칙 2칸) → 미리보기
3. `예비비` 체크 해제 → 22칸 적용 → 표 칸·kordoc 채우기 데이터·JSON·명령 확인
4. 다시 분류하면 이미 채운 22칸은 **체크 해제(유지)** 로 표시
5. 새로고침 후에도 채운 값·붙여넣은 글이 남음
6. 콘솔 오류 0건, 가로 넘침 0건(문서 scrollWidth == viewport)

같은 채움값 JSON으로 실제 kordoc 을 돌려 22개 칸이 원본 서식 그대로 채워지는 것도 확인했습니다.
