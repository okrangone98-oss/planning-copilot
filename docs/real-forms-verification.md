# 실제 기관 양식 10종 + 저장소 2종 검증 (PR #16)

실제 업무에서 쓰는 기관 양식 **10종**과 저장소 안의 양식 **2종**(연습 양식·결과보고 바탕)을
앱의 같은 코드 경로로 끝까지 돌린 결과입니다. 목적은 두 가지입니다.

1. 실전 양식에서 어디가 막히는지 **숫자로 확인**한다.
2. 확인된 호환성 문제를 **최소 변경**으로 고치고, 같은 문제가 다시 생기지 않게 회귀 테스트를 남긴다.

> **성격 구분** — 아래 표의 모든 값은 **기계가 확인한 것**입니다. 한컴오피스에서 직접 열어 본
> 결과(글꼴·표 테두리·인쇄 미리보기)는 **사람이 확인할 항목**으로 4장에 따로 두었습니다.
> 개인정보가 든 원본은 `work/real-forms/`에만 있고 **저장소에 커밋하지 않습니다.** 표에는 개인정보 값이 없고
> 탐지 **건수**만 적었습니다.

## 3. 이번에 고친 실전 호환성 문제

실제 10종을 돌려 드러난 문제만 골라 최소 변경으로 고쳤습니다. 각 항목에는 익명화한 합성 XML 픽스처 회귀 테스트가 있습니다
(`scripts/agent-office/test/real-form-compatibility.test.mjs`).

### 3.1 표 제목 띠를 라벨|값으로 읽던 문제

`강사카드`·`인적사항`·`강 의 사 진`처럼 **여러 열을 덮은 제목 칸**의 오른쪽 빈 칸을 값 자리로 보고, 값이 있으면
제목 띠 안에 써 넣었습니다(form4 강사 증빙, form6 이력서). 이제

- 여러 열을 덮은 칸(`colSpan` ≥ 열 수, 또는 3열 이상)은 **구역 제목**으로 보고 칸에서 뺍니다.
- 제목 띠 옆의 세로 병합 패널(인적사항 옆 정보 상자)은 값 칸이 아닙니다.
- 값 칸 안에 **표가 들어 있으면**(안내 상자) 덮어쓰지 않습니다.
- 표 스키마가 **병합 정보(`spans`)를 잃고 있던 버그**도 고쳐, 화면·사전 점검이 병합 표를 알 수 있게 했습니다.

### 3.2 병합 행 머리 오른쪽 열 머리를 값으로 채우던 문제

이력서의 `경력 | 기간 | 소속 | 담당과목`처럼 **행 머리가 여러 행을 덮은** 표에서, `기간`(열 머리)을 `경력`의
값으로 읽어 그 자리에 값을 썼습니다. form4의 `총액 | 원천세`도 같은 경우입니다. 이제 병합 행 머리 오른쪽이
열 머리면 그 행을 값 자리에서 제외합니다.

### 3.3 제목 띠 다음 줄의 열 머리 아래 빈 행 (빈 이력서)

`자격사항` 띠 아래 `경력 | 기간 | 소속 | 담당과목`이 있고 그 아래가 빈 이력서 양식은, 머리 줄을 라벨|값으로
읽어 칸이 거의 잡히지 않았습니다. 이제 **띠를 건너뛰고 열 머리를 찾아** 아래 빈 행을 칸으로 읽고,
같은 열 이름으로 행마다 값을 채웁니다(배열 값).

### 3.4 (서명/인) 자리를 ‘이미 적힌 값’으로 보던 문제

`성 명 | (서명/인)` 칸은 이름을 적는 자리인데 “이미 값이 있다”고 판단해 채우지 않았습니다.
이제 `(서명)`, `(서명 또는 인)`, `(인)`을 **값 자리 표시**로 읽어 이름을 채웁니다.

### 3.5 한 칸·한 문단 안의 인라인 서명 블록

계약서·서약서·동의서 끝의 서명란은 `성 명 : …  생년월일 : …  주 소 : …`처럼 **한 칸 안에 라벨이 줄지어**
들어 있습니다. 이 구조는 칸으로 전혀 읽히지 않아 계약서(form3)와 서약서(form7)가 “칸 0개”로 보였습니다.
이제

- 한 칸·한 문단에 신원 라벨(성명·생년월일·주소·연락처·소속·대표자 등)이 2개 이상이거나, 1개 + `(인)` 표시가 있으면
  **서명 블록**으로 보고 라벨별 칸을 만듭니다(이미 적힌 값은 `원본 유지`).
- 빈칸은 **같은 자리**(라벨 오른쪽)에 채우고, 옆 라벨·값 글자는 건드리지 않습니다.
- 금액·비목이 줄지은 예산 내역(`운영비 : 324백만원 - 인건비 : …`)은 서명 블록으로 보지 않습니다.

### 3.6 날짜 값이 라벨을 잡아먹던 문제

`생년월일 : 1983년 01월 03일 주 소 : …`에서 `일`이 다음 라벨(`주 소`)에 붙어 `일주소`가 되고
생년월일 값이 `1983년 01월 03`으로 잘렸습니다. 날짜(년·월·일) 뒤에 오는 라벨을 제대로 나눕니다.

### 3.7 법령·조례 본문의 ‘칸 0개’ 안내

법령·조례 본문(form8~10)은 채울 칸이 없는 것이 정상입니다. 이제 화면과 다운로드 전 사전 점검이
**“법령·조례 본문으로 보입니다 — 채울 칸이 없는 것이 정상입니다”**라고 먼저 안내하고,
“공고 해석·근거 확인에 쓰고, 채울 때는 신청서 양식을 올려라”는 다음 할 일을 함께 보여 줍니다.
일반 문서(회의록 등)는 기존의 “칸을 찾지 못했습니다” 안내를 유지합니다.

### 3.8 스키마 병합 정보 유지 (화면·사전 점검)

`parseSampleTemplate`이 표의 병합 정보를 버려, 사전 점검의 “병합된 칸이 있는 표” 안내가 한 번도 뜨지
않았습니다. 이제 병합 표가 스키마에 남아 4단계 사전 점검이 `직접 확인`으로 알려 줍니다(막지는 않음).

## 4. 사람이 반드시 확인할 항목 (자동 검증 불가)

- [ ] 받은 `.hwpx`가 한컴오피스에서 경고·복구 창 없이 열린다.
- [ ] 글꼴·글자 크기·표 테두리·병합 칸이 원본과 같다.
- [ ] 쪽 나눔·여백·인쇄 미리보기가 원본과 같다(특히 form1처럼 표가 많은 양식).
- [ ] 서명 블록에 넣은 값이 서명 자리와 겹치지 않는다.
- [ ] 그림·도장·직인 이미지가 그대로 남아 있다(form2·form5).
- [ ] 원본에 이미 있던 값이 지워지거나 바뀌지 않았다.
- [ ] 제출 기관이 요구하는 파일명 규칙에 맞게 저장했다.

## 5. 남은 한계 (아는 것과 모르는 것)

1. **form1 원본의 kordoc 문제 2건** — 원본 `content.hpf`가 사용자 PC의 절대경로 이미지 2개를 참조하고 있어
   `kordoc validate`가 실패합니다. 앱은 `content.hpf`를 건드리지 않으므로 채운 파일도 같은 2건입니다.
   (앱이 만든 문제가 아니며, 원본을 한글에서 다시 저장하면 정리됩니다. 경로 자체는 개인정보라 이 문서에 옮기지 않았습니다.)
2. **큰 양식의 칸 수** — form1은 인식 칸이 472개입니다. 화면은 60개까지 보여 주고 “더 있음”으로 접습니다.
   자동 배치가 어느 칸에 넣을지 고르는 데는 문제가 없지만, 사람이 전체를 훑기는 어렵습니다.
3. **이미 다 채워진 문서** — form3·5·6·7은 빈칸이 0개입니다. 앱은 원본 값을 덮어쓰지 않으므로
   “원본 유지” 칸으로만 보입니다. 값을 바꾸려면 한글에서 그 칸을 비우고 다시 올려야 합니다.
4. **다열 책임분담표** — form1의 `총 괄 | 빈칸 | 빈칸 | 담당부서` 같은 격자 표에서 일부 칸이 여전히
   라벨처럼 잡힙니다. 값이 자동으로 들어가지는 않지만(사용자가 그 칸에 값을 적어야 함) 칸 목록이 길어집니다.
5. **한컴오피스 실물 열기** — 이 환경에서는 확인할 수 없습니다. 4장 체크리스트로 남깁니다.
6. **AI 경로** — 개인정보 문서에서는 규칙 경로만 검증했습니다. AI 경로는 프롬프트를 `maskPii`로 가린 뒤
   보내는 것까지만 테스트로 확인했고, 실제 외부 모델 호출은 하지 않았습니다(비용 0원 원칙·키 없음).
