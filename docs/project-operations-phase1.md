# 사업 운영(1단계 P0) — 설계와 사용법

2026-11-15 · Planning Copilot · PRD v1.1 1단계(P0)

계획서·예산을 만드는 화면은 그대로 두고, **확정된 사업 하나를 운영하는 데이터**를 붙였습니다.
새 메뉴는 만들지 않았습니다. 모든 화면은 `사업 관리` 안의 네 탭(개요 / 업무·일정 / 회차 / 예산·집행)과 시작 화면에만 있습니다.

## 1. 한눈에

| 하려는 일 | 어디서 |
| --- | --- |
| 사업 정보(연도·담당자·기간·목표·상태) 고치기 | 사업 관리 → 카드의 `상세` → `개요` |
| 계획을 확정하고 운영 업무 만들기 | `개요` → `계획 확정` |
| 업무·기한 관리, 지연 확인, 달력 보기 | `업무·일정` |
| 10회차 같은 회차 관리, 회차 취소 | `회차` |
| 계획액·비목·시트/CSV 가져오기 | `예산·집행` |
| 오늘 마감·지연·다음 할 일 하나 | 시작 화면 → `오늘 할 일` |
| 변경 전후 값과 사유 | `개요` → `변경 이력`, `계획 리비전` |

## 2. 저장 구조

모두 브라우저 localStorage에 둡니다(서버 없음).

| 키 | 내용 | 스키마 |
| --- | --- | --- |
| `planningCopilotWorkspace` | 사업 목록·활성 사업 | `schemaVersion: 3` |
| `planningCopilotProject:{id}` | 사업계획 입력값 | 필드 허용목록 |
| `planningCopilotGrantPlan:{id}` | 예산·증빙·보고서·일정 | `1` |
| `planningCopilotTemplateSession:{id}` | 양식 채우기 세션 | — |
| `planningCopilotProjectWork:{id}` | 업무·회차·지출 원장·리비전·변경 이력·생성 기록 | `1` |

- **금액의 유일한 원천은 `grantPlan.budgetLines`** 입니다. 운영 데이터에는 금액 필드가 아예 없어서 이중 합산이 구조적으로 불가능합니다. 개요·예산 탭의 계획액은 `budgetSummary()` 결과를 그대로 보여 줍니다.
- 운영 데이터가 비어 있으면 저장 키를 만들지 않습니다(사업을 열어 보기만 해도 키가 생기지 않음).
- 사업 삭제는 4개 키(계획·예산·양식·운영)를 함께 지웁니다. 복제는 업무·회차를 새 id로 한 벌 더 만들고, 멱등 키(`sourceKey`)는 유지합니다. 변경 이력은 원본 기록이라 복사하지 않습니다.

## 3. 상태 11종

`idea` 아이디어 · `planning` 기획 중 · `submitted` 신청 완료 · `review` 검토 중 · `confirmed` 확정 · `preparing` 운영 준비 · `running` 운영 중 · `settling` 정산·평가 · `done` 완료 · `hold` 보류 · `cancelled` 취소

- 기존 4개 id(`planning`/`submitted`/`running`/`done`)는 유지했습니다. `running` 라벨만 "집행·정산" → "운영 중"으로 바뀌었고 저장 값은 그대로입니다(기존 사업 손실 없음).
- 완료·보류·취소 사업은 보드 아래로 내려갑니다.
- `확정` 이전(아이디어·기획·신청 완료·검토 중)에는 **미리보기만** 되고 업무 생성은 막습니다. `확정` 이후에만 만들 수 있고, 완료·보류·취소에서는 만들 수 없습니다.

## 4. 계획 → 운영 전환

1. `개요` → `계획 확정`에서 **공고문 없이도** 확정할 수 있습니다. 사업 기간·목표·예산이 비어 있으면 경고만 남깁니다.
2. 회차 수(기본 1, 최대 60)를 정하고, 빼고 싶은 단계를 눌러 끕니다(템플릿은 필수가 아님).
3. 미리보기 표에서 무엇이 `신규`/`유지`인지 확인한 뒤 확정합니다. 확정하면
   - 그 시점 계획 스냅샷이 `계획 리비전`으로 남고(사유 포함),
   - 확정 전이었다면 상태가 `확정`으로 바뀌고,
   - 12단계 업무 초안과 회차(회차가 없을 때)가 만들어집니다.
4. 다시 실행해도 **같은 업무는 중복 생성되지 않습니다.** 멱등 키는
   `phase1.v1:{단계}:{회차번호|0}:{업무slug}` 이고, 이미 있는 키는 건너뛰므로 사용자가 고친 제목·기한·상태가 유지됩니다.
5. 회차를 추가한 뒤 다시 실행하면 그 회차 몫만 새로 만들어집니다.

### 12단계 템플릿(`src/lib/stageTemplate.mjs`)

사업기획 · 계획·예산 · 검토·승인 · 자원확보 · 홍보·모집 · 운영 준비 · 실행 · 변경·이슈 대응 · 증빙 관리 · 예산 정산 · 성과 평가 · 결과보고·환류

- 회차별 단계(운영 준비·실행·변경·이슈)는 회차 수만큼 업무가 생깁니다(회차 1개 = 회차 업무 6개, 회차 10개 = 60개).
- 기한은 사업 시작일·종료일·회차 일시에서 계산합니다. 날짜가 없으면 기한을 비워 두고, `일괄 날짜 변경`으로 채웁니다.
- 단계를 건너뛰면 그 단계 업무와, 그 업무를 가리키던 선행 관계도 함께 빠집니다.

## 5. 업무·일정

- 요약: 전체 / 남은 일 / 지연 / 오늘 마감 / 완료율(취소 업무는 분모에서 제외).
- 거르기: 전체·남은 일·지연·오늘 마감·완료 + 단계 + 회차 + 검색.
- 목록: 완료 칸을 누르면 바로 완료(변경 이력에 남음), 업무명을 누르면 담당·기한·상태·우선순위·완료 조건·선행 업무(최대 5)를 고칩니다. 선행 업무가 끝나지 않으면 `대기`로 표시합니다.
- 달력: 외부 라이브러리 없이 CSS grid. 이번 달에 일이 없으면 일이 있는 가장 가까운 달을 먼저 보여 줍니다.
- 일괄 날짜 변경: 대상(전체/단계/회차) + 방식(며칠 미루기/한 날짜로) → **미리보기(몇 건, 전후 날짜)** → 적용. 적용 전에는 원본이 바뀌지 않습니다.

## 6. 회차

- 회차별 제목·일시·장소·강사·정원·신청·참석·상태·메모.
- 집계는 **취소 회차를 빼고** 셉니다(정원·신청·참석 합계). 회차 수에는 남습니다.
- 취소는 삭제가 아니라 상태 전입니다. 연결된 업무는 기본 `보류`로 두고 사용자가 다시 엽니다. `되돌리기`로 예정으로 되돌릴 수 있습니다.

## 7. 변경 이력과 리비전

- 남기는 곳: 사업 정보(사업명·유형·상태·연도·담당자·기간·마감·목표·출처), 업무(제목·단계·회차·담당·기한·상태·우선순위·완료 조건·선행), 회차(번호·제목·일시·장소·강사·인원·상태·메모), 예산(사업명·재원 기관·사업 기간·결과보고 마감·비목 수와 합계).
- 값은 120자, 사유는 200자에서 자르고 300건까지만 보관합니다.
- 같은 편집이 한 줄로 남도록 예산 입력은 5분 안의 같은 필드 변경을 마지막 값으로 합칩니다.
- 계획 리비전은 확정 시점의 사업 정보·계획서 핵심 항목·예산 행·일정을 담습니다.
