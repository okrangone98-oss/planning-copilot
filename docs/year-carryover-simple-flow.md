# 전년도 결과보고서 이양 — 3단계 간단 화면

작년 결과보고서를 올해 것으로 바꿔 쓰는 일은 실제로는 "작년 문서를 열고 숫자만 고치는" 일이다.
이 문서는 첫 화면의 큰 버튼 **`🔄 작년 결과보고서 → 올해 것으로 바꾸기`** 로 들어가는 3단계 화면과,
그 화면이 `.hwpx` 안에서 값을 찾아 갈아끼우는 규칙을 정리한다.

## 화면

| 단계 | 하는 일 | 화면이 하는 일 |
| --- | --- | --- |
| 1 | 작년 결과보고서(`.hwpx`) 올리기 | 표·문단·문서 제목에서 값을 읽어 칸으로 만들고, 전년도 값(연도·날짜·금액·인원)이 적힌 칸을 **이양 대상**으로 표시 |
| 2 | 올해 자료 넣기(계획서 `.hwpx`·정산 CSV·실적 메모) | 계획서에서 사업명·기간·예산·일정을 읽어(결재란·주소·연락처·뒤에 붙은 계약서/동의서는 제외) 3단계 값으로 배치 |
| 3 | 바뀐 항목만 검토하고 `.hwpx` 내려받기 | 바뀐 칸·작년 값이 남은 칸을 배지로 표시, 값은 그 자리에서 수정, 확신이 낮은 자동 배치는 **체크하지 않은 채** 남김 |

"전체 화면 보기"를 누르면 기존 4단계 화면(양식 구조·AI 초안·kordoc JSON·브릿지 등)이 그대로 나온다.
3단계 화면은 같은 상태(`templateSession`)를 쓰므로 어느 쪽에서 고쳐도 결과는 하나다.

## 표 밖 문단 읽기

결과보고서는 정산내역 표 말고 **본문 문단**에 핵심 값을 적는다.

```
2025년 의기양양 활동가 양성 사업 결과보고서      ← 문서 제목(연도 머리글)
가.사 업 명: 2025 의기양양 활동가 양성 사업     ← 라벨: 값
나.사업기간: 2025년 6월 10일 ~ 2025년 11월 28일
1)총 운영회차: 34회
총 참여 인원(누적): 658명                      ← 라벨에 괄호가 섞인 줄
```

- `extractHwpxBlocks` 는 문단 안 줄바꿈(`<hp:lineBreak/>`)에서 문단을 끊는다. 한 문단에 여러 줄이 몰려
  있으면 240자 제한에 걸려 라벨을 못 읽던 문제가 여기서 풀린다.
- `labelledParagraphParts` 가 줄 첫머리의 라벨만 골라 `라벨: 값` 으로 나눈다. 문장 속 콜론, 안내문(※),
  서명 블록(성명·생년월일·주소)은 값 칸이 아니다.
- `detectDocumentTitleText` 는 연도가 박힌 짧은 문서 이름만 제목으로 본다. 표 칸에 들어 있는 제목도 읽는다.

## 값 갈아끼우기 세 가지 길

| 종류 | 대상 | `.hwpx` 에 쓰는 방법 |
| --- | --- | --- |
| `labelled`(inline) | 라벨 위치를 정확히 짚을 수 있는 줄 | `라벨: 값` 의 **값 글자만** 바꾼다 — 라벨 글자와 `charPrIDRef`(글꼴·크기) 유지 |
| `labelled-text`(affix) | `총 참여 인원(누적): 658명` 처럼 라벨에 괄호가 섞인 줄 | 줄 첫머리(`prefix`)는 그대로 두고 값만 바꾼 글자로 **문단 글자를 통째로** 바꾼다 |
| `title`(text) | `2025년 … 결과보고서` | 원문 글자와 **정확히 같은 문단**만 새 제목으로 바꾼다(다른 문단·사람이 고친 글은 건드리지 않음) |

- 라벨 기반 채우기는 `carryoverOverwriteMap`(라벨 키 → 바꾸기 전 글자)에 **정확히 같은 글자**가 있을 때만 덮어쓴다.
- 라벨이 없는 제목은 `buildTextRewrites` 가 `{from, to}` 목록을 만들어 넘기고,
  `patchHwpxBytes({ rewrites })` 가 그 글자와 같은 문단을 찾아 바꾼다.
- 바꾼 문단의 `hp:linesegarray`(옛 줄 배치)는 지운다 — 한글에서 열었을 때 이전 배치가 남지 않게.

## 자동 배치 안전장치

이미 값을 덮어쓰는 일이라, 자동 배치는 확신이 있을 때만 체크한다.

- 라벨이 정확히 같은 계획서 줄은 그 칸에 먼저 붙인다(`mapFreeTextToFields` ①단계).
  이 과정이 없으면 `사업명:` 줄이 다른 칸에 먼저 붙어 정작 사업명 칸이 비는 일이 생겼다.
- `적용 전 점수`가 `CARRYOVER_MIN_SCORE`(0.7)보다 낮은 칸은 **체크를 풀어** 사람이 보게 한다(`applyCarryoverGuard`).
- 문서 제목은 계획서 사업명으로 `2026년 {사업명} 결과보고서` 를 제안하고, 사업명이 없으면 연도만 바꾼다.
  넣은 제안은 3단계 표에서 그대로 고칠 수 있다.

## 계획서(기안문)에서 걷어 내는 것

`hwpxSourceExtractor` 는 결재 문서 껍데기를 결과보고서 재료로 옮기지 않는다.

- 결재란(팀장·사무국장·센터장·협조자), 수신·경유·시행·접수, 붙임 줄
- 기관 주소·우편번호, 전화·팩스, 이메일(개인정보이기도 하다)
- 본문 뒤에 붙은 **계약서·매뉴얼·신청서·동의서·인적카드·청구서** — 제목 줄을 만나면 거기서 멈춘다
- 같은 항목의 값이 다르게 적혀 있으면(예: 기안문 예산 3천만 원, 본문 예산 2천만 원) 화면에 그대로 알린다

## 남은 한계

- 정산표의 **여러 행**을 올해 값으로 자동 매칭하지는 않는다. 비목 이름이 같아도 행 순서·개수가 다르면
  사람이 봐야 하므로, 표 행은 자동으로 체크하지 않고 `비목 · 집행액` 같은 이름으로만 제안한다.
- 계획서에 없는 항목(작년 실적 숫자 등)은 바꿀 값이 없어 **`전년도 값 잔존 확인 필요`** 로 남는다. 이건 의도된 동작이다.
- 라벨에 괄호가 섞인 줄(affix)은 문단 글자를 통째로 바꾸므로, 라벨과 값의 글자 모양이 서로 다르면
  값 쪽 글자 모양을 따른다. 내려받은 문서를 한글에서 한 번 확인해야 한다.
