# 실무 중심 제품 정리 구현 계획

## 목표

기존 프로젝트 데이터와 화면 기능을 보존하면서 탐색 메뉴를 5개 업무 영역으로 단순화하고, AI 사무국이 선택된 로컬 Ollama 모델을 실제로 사용하도록 연결한다. 모델 실행이 아닌 역할별 프롬프트/템플릿 결과는 시뮬레이션임을 명확히 표시한다.

## 구현 단계

- [x] 1. 구현 경계 확인: 타입, 저장소, 모델 라우터, 사무국, 내비게이션 및 스타일 접점을 확인한다.
- [x] 2. 모델 안전성: 제공자를 시뮬레이션/Ollama로 제한하고, 이전 브라우저 키는 모델 설정 항목에서만 제거한다.
- [x] 3. 실무 실행: 명령 실행을 비동기로 바꾸고, Ollama 결과·오류·입력 범위를 명확하게 연결한다.
- [x] 4. 메뉴 재구성: 5개 업무 영역으로 묶고 기존 화면은 하위 메뉴로 유지한다.
- [x] 5. 검증 및 문서: 핵심 실행/설정/메뉴 테스트와 프로젝트 전체 검사 후 완료 기준과 남은 제한을 기록한다.

## 제약과 완료 기준

- 새 의존성, API 키 입력, 자동 발송/외부 쓰기, 기존 로컬 데이터 삭제는 하지 않는다.
- Ollama 외부 호스트로의 프로젝트 자료 전송은 차단하고 loopback 주소만 허용한다.
- 모든 기존 화면 ID를 유지해 기존 프로젝트 데이터의 연결을 보존한다.
- `npm run office:test`와 `npm run check`가 통과한다.
- 기본 탭에서 5개 영역이 보이고 하위 메뉴 선택으로 모든 기존 기능에 접근할 수 있다.
- Ollama 미설치/실패를 템플릿 응답으로 조용히 대체하지 않는다.

## 완료 기록

2026-10-04 로컬 구현과 검증을 완료했다. `npm run office:test` 68개 통과, `npm run check` 종료 코드 0, `git diff --check` 오류 없음. 별도 lint 스크립트는 없으며 기존 큰 번들 경고는 남아 있다.

격리된 Playwright 브라우저에서 데스크톱 1440×1000과 모바일 390×844의 기존 20개 화면, 템플릿 실행, 설정 마이그레이션, 승인·기억 저장을 확인했다. 모의 Ollama API로 통합 보고 생성과 실패·원격 모델 차단을 검증했고 브라우저 오류 및 가로 넘침은 없었다. WSL 파일 변경 감지 지연으로 개발 서버를 재시작한 후 최신 화면을 재검증했다.

실제 Ollama 서버가 실행되지 않아 실제 모델 추론 품질은 미검증이다. 실제 Google OAuth 계정 접근, GitHub 푸시, 배포는 수행하지 않았다. 사용 순서와 데이터 경계는 `docs/practical-product-usage.md`에 기록했다.
