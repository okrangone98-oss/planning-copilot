# 샘플 양식 구조 파싱 · 맞춤 채우기

공고·기관에서 받은 **사업계획서 양식 파일**을 올리면, 그 양식의 **목차 계층 · 표 구조(열 머리글/행/빈칸) · 작성 항목**을 먼저 읽어 보여 주고, 내 사업 정보로 **같은 구조를 유지한 Markdown 초안**을 만듭니다.

1단계는 **웹 단독**입니다. 파일은 브라우저 밖으로 나가지 않고, 문서 파싱도 브라우저 안에서 끝납니다. AI를 부르는 시점에만 사용자가 고른 경로(템플릿/Ollama/무료 API)로 정리된 프롬프트가 나갑니다.

## 화면 흐름

`산출물·검토 → 샘플 양식 채우기` (또는 시작 화면의 `이미 쓰는 양식이 있나요?` 바)

1. **양식 올리기** — 파일 업로드 또는 붙여넣기
2. **구조 미리보기** — 섹션 목차, 표의 열·행과 빈칸, 작성 항목(빈칸·라벨·작성 요령·목록 항목)을 즉시 표시
3. **내 사업 정보** — 사업명·기관·지역·대상·핵심 메모·예산·일정·보유 자료. `프로젝트 입력값 가져오기`로 좌측 프로젝트명과 예산·정산 화면의 값을 채웁니다.
4. **이 양식에 맞춰 채우기** — AI 호출. 실패하면 규칙 기반 초안 + 프롬프트 복사 폴백
5. **결과** — 원본 목차·표를 유지한 Markdown. 복사 / `.md` 받기 / 워크브레인 내보내기 / 승인함 / 초안 조립으로 연결

시작 화면의 `기존 문서 불러오기` 카드는 지금처럼 공고 해석으로 연결되고, 양식 채우기는 같은 영역의 별도 바에서 시작합니다. `자료·근거 → 샘플 분해`와 `산출물·검토 → 초안 조립` 화면에도 양식 채우기로 가는 버튼을 두었습니다.

## 지원 형식과 한계

| 형식 | 읽는 방법 | 구조 인식 |
| --- | --- | --- |
| HWPX | ZIP + `Contents/sectionN.xml` 파싱 | 문단·표(행/칸)까지 |
| DOCX | mammoth `convertToHtml` 후 제목·표·목록 파싱 | 제목 스타일·표까지 |
| PDF | pdf.js 텍스트 추출(같은 높이 글자를 한 줄로) | 제목·번호 목차 위주. 표는 텍스트층에 구분자가 있을 때만 |
| MD / TXT / CSV / HTML | 텍스트 → 블록 | Markdown 표·탭 표·번호 목차 |

- **구형 `.hwp`(바이너리)는 브라우저에서 구조를 읽을 수 없습니다.** 올리면 “한글에서 HWPX로 저장하거나 DOCX·PDF로 변환해 올려 주세요” 안내가 뜹니다. HWP5(OLE2)·OCR·병합 셀 복원은 로컬 [kordoc](https://github.com/chrisryugj/kordoc)이 필요한 영역이라 1단계에서는 붙이지 않았습니다.
- HWPX 병합 칸은 첫 칸 위치에만 글자가 담기므로, 빈칸 수가 실제보다 많게 보일 수 있습니다.
- 스캔 이미지 PDF는 OCR이 없어 글자를 읽지 못합니다.

## 구조 모델 (kordoc IR 개념의 브라우저 구현)

kordoc의 `IRBlock[]` → Markdown 파이프라인과 같은 순서를 씁니다. 다만 브라우저에서 의존성 없이 돌도록 최소 구현입니다.

```
문서 → 블록(IRBlock: heading / paragraph / list / table) → 양식 스키마(섹션 · 표 · 슬롯) → 미리보기 · 프롬프트 · 규칙 기반 채우기
```

- `src/lib/sampleTemplateParser.mjs` — 블록 파서(HWPX XML·DOCX HTML·평문), 제목 계층 판정, 표·슬롯 추출, 미리보기, 프롬프트, 규칙 기반 채우기
- `src/lib/fileText.ts` — 기존 추출기를 `extractDocument()`로 확장(텍스트 + 블록). 기존 `extractTextFromFile()`은 그대로 남아 공고문·사례 화면이 같은 파일을 씁니다.
- `src/components/TemplateFillView.tsx` — 미리보기·프로필·실행·결과 화면
- `src/lib/templateStorage.ts` — 이 브라우저에 양식 스키마·프로필·결과 저장(모양 검증 후)

제목 계층은 Markdown `#`, `Ⅰ.`, `1.`, `1)`, `가.`, `(1)`, `①`, `【…】` 표기를 인식하고, 문서에 나타난 단계만 1..n으로 압축합니다.

작성 슬롯은 다음 네 가지로 나눕니다.

| 종류 | 예 |
| --- | --- |
| 빈칸 `blank` | `사업명: ______`, `추진 기간: (    )` |
| 라벨 `label` | `담당자:` 처럼 값 없이 끝나는 줄 |
| 작성 요령 `guide` | `○ (작성 요령) …`, `※ …` — 결과물에는 옮기지 않음 |
| 목록 항목 `item` | 양식의 `○`·`-` 목록 |
| 표 빈칸 `table-cell` | 표의 빈 칸(행·열 지정) |

## AI 채우기와 폴백

- 호출은 기존 `freeModelRouter`(`runModelPrompt`)를 그대로 씁니다. 키는 브라우저 메모리에만 있습니다.
- 프롬프트에는 **읽은 양식 구조 전체**와 내 사업 정보가 들어가고, “목차 순서·제목 유지 / 표 열 이름 유지 / 작성 요령은 옮기지 않기 / 없는 수치는 확인 필요”를 명시합니다.
- 실패(키 거부·한도·CORS·네트워크) 시 같은 구조로 **규칙 기반 초안**을 자동으로 채우고, **프롬프트 복사**로 외부 AI에 이어가거나 **모델 설정**으로 바로 갈 수 있게 합니다.
- 결과가 양식 제목을 얼마나 지켰는지 세어(`checkStructureCoverage`), 절반 이상 빠지면 목차 검토를 안내합니다.

규칙 기반 채우기는 AI 없이도 동작합니다. 표의 빈 칸은 열 이름을 보고 사업명·기관·지역·대상·예산·일정·내용·근거 값을 넣고, 값이 없으면 `확인 필요`로 남깁니다. **샘플에 원래 적혀 있던 글은 지우지 않고 그대로 둡니다.**

## 3단계 검토 · 4단계 사전 점검 (PR #15)

4단계 흐름은 그대로 두고, 3·4단계 안에서 “지금 어느 칸이 비었고 무엇을 확인해야 하는지” 보이게 했습니다.

- **3단계 칸 상태** — 값이 있는 칸은 `자동 채움`(2단계 배치 결과) · `값 있음`(직접 적음) · `확인 필요`(형식 오류·자동 배치 신뢰도 낮음),
  값이 없는 칸은 `빈칸` · `빈칸 · 필수`(라벨에 ※·(필수)) · `원본 유지`(원본에 이미 값이 있음, 덮어쓰지 않음)로 구분합니다.
  맨 위에 상태별 개수를, 표에는 칸마다 배지를 보여 줍니다.
- **입력칸 높이** — 검토 표 입력칸은 내용 길이에 맞춰 늘어납니다(`src/components/AutoGrowTextarea.tsx`).
  처음 그릴 때·타이핑할 때·밖에서 값이 바뀔 때(저장값 복원) 모두 다시 재고, 화면 폭이 바뀌면 다시 잽니다.
- **아직 비어 있는 칸** — 표에 값이 있는 칸만 보이던 것을, 비어 있는 칸 목록(필수 표시 먼저)에서 바로 적을 수 있게 했습니다.
  원본에 값이 있는 칸은 고칠 수 있는 칸이 아니므로 지금 값을 보여 주기만 합니다.
- **4단계 사전 점검** — 필수값 누락, 날짜·금액 형식, 한 칸에 값 두 줄, 같은 이름의 칸, 배치하지 못한 글,
  예산 총액-비목 합계, 출석 미입력과 0명, 결과보고서 불완전, 병합 칸, 원본 값 유지, 파일 없음을 모아 보여 줍니다.
  항목은 `꼭 확인`(한 번 더 누르면 그대로 내려받음) · `확인 권장` · `직접 확인`(앱이 판단할 수 없음) 세 단계이며,
  점검은 어떤 값도 고치지 않습니다. 규칙은 `src/lib/downloadPreflight.mjs` 한 곳에 있습니다.
- **실패 안내** — `.hwpx` 생성 실패를 zip 아님·본문 없음·메모리 부족으로 나눠 쉬운 한국어 이유와 다음 할 일을 보여 주고,
  “입력한 값은 그대로 남아 있다”를 함께 알립니다.

변경 파일: `src/components/KordocFillPanel.tsx`, `src/components/TemplateFillView.tsx`, `src/components/AutoGrowTextarea.tsx`(신규),
`src/lib/downloadPreflight.mjs`(+`.d.mts`, 신규), `src/styles/screens.css`.
실무 측정 지표와 시나리오 A·B·C 자동 검증 결과는 [실무 사용성 측정표](field-usability-checklist.md)에 있습니다.
