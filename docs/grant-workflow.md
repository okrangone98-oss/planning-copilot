# 국고보조사업 예산·정산·결과보고 모듈

기존 `공고 해석 → 아이디어 → 문제정의 → 논리모형 → 성과지표 → 실행설계 → 초안 조립` 흐름은 그대로 두고, 그 뒤에 이어지는 **연중 실무(예산 편성 → 집행·증빙 점검 → 결과보고)** 를 같은 프로젝트 안에서 다루도록 붙인 모듈입니다.

## 화면

| 메뉴 | 하는 일 |
| --- | --- |
| 예산·정산 → 예산 편성 | 비목별 예산표(단가×수량 자동 계산), 재원 구성(국비·지방비·자부담), 사업 기본 정보, 추진 일정·마감 |
| 예산·정산 → 정산 증빙 | 교부·집행·인건비·실적·마감 증빙 체크리스트(진행률, 필수 항목, 항목별 메모, 직접 추가) |
| 예산·정산 → 결과보고 | 기관 결과보고 양식 순서의 섹션별 초안 작성(프로젝트 입력값에서 빈 섹션만 채우기) |

## 프리셋

`src/data/grantPresets.json`에 세 가지 프리셋이 있고, 화면에서 골라 적용합니다. 적용 후에는 모든 행·항목·섹션을 직접 고칠 수 있습니다.

| 프리셋 | 기준 |
| --- | --- |
| 국고보조사업 표준(농촌활성화지원센터) | 교부→집행→정산→결과보고 전 과정. 비목 12개·증빙 22개·보고서 8섹션 |
| 2026 시군역량강화사업(센터 운영) | 센터 운영비+사업비 혼합 구조, 연말 실적·정산 보고 |
| 공모사업(청년·관광두레) | 협약 기반 공모사업, 중간·최종 보고 |

프리셋을 다시 적용하거나 다른 프리셋으로 바꾸면 **같은 항목(비목·세목, 점검 항목, 결과보고 섹션 제목)의 체크 상태·메모·작성 내용은 유지**됩니다. 금액·산출근거·섹션 골격은 프리셋 값으로 다시 잡히므로, 직접 고친 금액이 있으면 적용 전에 확인 창에서 한 번 더 묻습니다.

## 화면 이동과 좁은 화면

- 네 화면(예산 편성·정산 증빙·결과보고·워크브레인 내보내기)에는 화면 하단에 고정된 이동 바가 있습니다. 진행률과 이전/다음 단계가 항상 보이므로 긴 예산표 끝까지 스크롤할 필요가 없습니다(safe-area 여백 포함, 모바일 메뉴를 여는 동안만 숨김).
- 768px 이하에서는 예산 편성표가 요약 한 줄(비목·세목·금액) 아코디언으로 바뀝니다. 행을 누르면 상세 입력이 펼쳐지고, `항목 추가`로 만든 새 행은 펼친 채로 시작합니다.
- 단가 칸은 쉬고 있을 때 콤마 표기(`250,000`)로 보이고, 입력 중에는 친 그대로 둡니다.

## 계산 규칙

- 금액 = 단가 × 수량. 단가는 `250000`, `250,000원`, `25만원` 모두 인식하고, 수량은 `8`, `8회`, `2.5`처럼 적어도 됩니다.
- 재원 구성은 사업 총액 × (국비%·지방비%·자부담%)이며 10원 단위로 반올림합니다.
- 입력한 비율 합이 100%가 아니면 자부담을 잔액으로 계산하고, 그 사실을 화면과 내보내기 문서에 표시합니다. 비율을 임의로 보정하지 않습니다.
- 정산 진행률은 체크한 항목 수 기준이며, 필수 항목 완료 수를 따로 보여 줍니다.

## 저장

- 예산·정산 데이터는 `localStorage`의 `planningCopilotGrantPlan` 키에 따로 저장합니다. 사업계획서 데이터(`planningCopilotProject`)와 섞이지 않습니다.
- 저장할 때는 허용 목록(`sanitizeGrantPlan`)으로만 기록합니다. 화면이나 다른 코드가 붙인 알 수 없는 필드(키·토큰 등)는 저장되지 않습니다.
- 백업 파일(아카이브)은 version 5로 올라가고 `grantPlan`을 함께 담습니다. 4 이하 백업도 그대로 복원됩니다.

## 범위 밖

- 회계 프로그램·보조금통합관리시스템과의 연동은 없습니다. 이 화면은 편성표와 점검표를 만들고, 실제 집행·증빙 원본은 기존 기관 절차대로 보관합니다.
- 증빙 원본 파일은 담지 않습니다. 파일명·보관 위치 정도만 메모로 남깁니다.
- 세무·회계 판단(비목 전용 한도, 간접비 상한 등)은 기관 지침과 담당자 확인이 우선입니다.

## 검증

- `node --test`(=`npm test`, `npm run office:test`): 프리셋 무결성, 금액·재원 계산, 프리셋 재적용 시 진행 상태 유지, 저장값 허용 목록, D-day·후속 할 일 테스트 포함 97개 통과.
- Playwright 헤드리스(1440×1000, 390×844)에서 프리셋 적용 → 예산 24,180,000원·12비목 계산, 체크리스트 22항목·1건 체크, 결과보고 초안 채우기, 내보내기 미리보기 5,392자 생성을 확인했습니다. 화면 23개 메뉴 전환에서 콘솔 오류·가로 넘침은 없었습니다.
- 2차 UX 보완 검증(같은 뷰포트): 하단 고정 이동 바가 문서 맨 위·맨 아래 모두 화면 하단(1440: top 925/1000, 390: top 751/844)에 있고, 모바일 예산 아코디언 12행 접힘 상태에서 문서 높이 5,020px(이전 12행 카드형 9,914px), 펼쳐서 단가 입력 후 blur `2,200,000`·금액 `17,600,000원`, 새로고침 후 값 유지, 새 행 펼침, 사이드바 그룹 교체(업무 홈+현재 그룹만), 상단 토스트(390: top 12~60px, 하단 바와 미중첩), 체크박스 22×22px·행 112px, 콘솔 오류 0·가로 넘침 0(360~1440 12구간)을 확인했습니다.
