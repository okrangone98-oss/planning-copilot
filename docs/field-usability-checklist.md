# 실무 사용성 측정표 — 양식 채우기 (Planning Copilot)

이 문서에는 **성격이 다른 세 가지 숫자**가 있습니다. 섞으면 “기계가 확인한 것을 사람이 확인한 것처럼” 보이므로
표마다 성격을 먼저 밝힙니다.

| 층 | 무엇 | 지금 상태 |
| --- | --- | --- |
| 1장 | **목표치** — 이 화면이 넘어야 할 선 | 목표일 뿐, **아직 재지 않았습니다** |
| 2장 | **사람이 재는 8지표 측정표** — 실무자 한 사람이 실제 양식으로 끝까지 써 보고 적는 칸 | 비어 있음(측정 전) |
| 3장 이후 | **기계가 확인한 것** — 같은 코드 경로를 자동 테스트로 돌린 결과 | 2026-11-16, 자동 검증 완료 |

측정 대상 양식(원본은 `work/real-forms/`, 저장소에 커밋하지 않음): ① 2027년 양양군 시군역량강화사업 예비계획서
② 내가그린양양 강사료 청구서 ③ 내가Green양양 위촉계약서 서식1. 저장소 안의 연습 양식은 자동 검증(3장)에만 씁니다.

## 1. 8가지 지표와 목표치 (목표치일 뿐 · 미실측)

| # | 지표 | 세는 법 | 목표치 | 실측 |
| --- | --- | --- | --- | --- |
| 1 | 작업 완료 여부 | 4단계를 끝내 `.hwpx`를 받았는가 | 양식 3종 모두 완료 | 미실측 |
| 2 | 총 소요시간 | ① 양식 불러오기 시작 → ④ 내려받기 완료 (한글에서 최종 손보는 시간은 따로) | 같은 양식을 한글에서 처음부터 채우는 시간의 **50% 이하** | 미실측 |
| 3 | 자동 입력 성공 수 | 내가 고치지 않아도 맞게 들어간 칸 수 | 인식한 빈칸의 **60% 이상** | 미실측 |
| 4 | 직접 수정 수 | 값은 들어갔지만 내가 고친 칸 + 값이 안 들어가 내가 채운 칸 | 자동 성공 수의 **30% 이하** | 미실측 |
| 5 | 누락·오기입 | 값이 빠진 칸 · 다른 칸에 들어간 값 · 숫자·날짜가 틀린 건의 합 | **0건** (1건이면 원인 기록) | 미실측 |
| 6 | 출력 정상 여부 | 받은 `.hwpx`가 한글에서 경고 없이 열리고 서식·표·병합이 원본과 같은가 | 3종 모두 정상 | 미실측 |
| 7 | 도움 필요 횟수 | 혼자 하다가 다른 사람·검색에 물어본 횟수 | **2회 이하** | 미실측 |
| 8 | 재사용 의향 | “다음에도 쓰겠는가” (예 / 조건부 / 아니오 + 이유) | 예 또는 조건부(이유가 고쳐질 수 있는 것) | 미실측 |

목표치는 이번 PR에서 정한 **선**이고, 측정표가 채워지면 목표에 못 미친 지표를 먼저 손봅니다.
목표치를 넘겼다는 표시가 없으면 아직 달성했다는 뜻이 아닙니다.

보조 기록: 측정일 / 측정자 / 브라우저·기기 / 앱 빌드(커밋) — ______________________

### 측정 전 준비

1. 개인정보(주민등록번호·연락처·성명)를 지운 사본으로 측정합니다. 원본 파일은 고치지 않습니다.
2. 기존 방식(한글에서 열어 채우고 저장)의 시간을 먼저 잽니다.
3. 막힌 지점이 나오면 그 자리에서 지표 7의 횟수를 하나 올리고, 어느 단계에서 막혔는지 적습니다.
4. 받은 `.hwpx`는 한컴오피스에서 직접 열어 4장 항목을 확인합니다.

### 같은 기준으로 세는 법

- **2 총 소요시간**: 파일 찾는 시간은 빼고, ①단계 시작부터 ④ 내려받기 완료까지. 한글에서 최종 손보는 시간은 따로 적습니다.
- **3 자동 입력 성공 수**: 손대지 않아도 맞게 들어간 칸. 자동 배치가 넣었지만 내가 고친 칸은 4번으로 셉니다.
- **4 직접 수정 수**: 값은 들어갔는데 고친 칸 + 비어 있어 내가 채운 칸.
- **5 누락·오기입**: 빠진 칸, 다른 칸에 들어간 값, 숫자·날짜 오류를 합쳐 셉니다(0이면 0이라고 적습니다).
- **7 도움 필요 횟수**: 화면 안의 안내(3단계 상태 표시·4단계 사전 점검)를 읽고 혼자 해결한 것은 세지 않습니다.

## 3. 기계가 확인한 것 — 자동 검증 (사람 측정 아님)

아래 값은 브라우저 없이 앱의 같은 코드 경로(양식 읽기 → 칸 인식 → 자유 텍스트 배치 → 사전 점검 → HWPX 패치)를
그대로 돌린 결과입니다. **사람의 작업시간·느낌·재사용 의향이 아닙니다.**

```bash
npm test                                        # 전체 321개
node --test scripts/agent-office/test/field-scenarios.test.mjs   # 시나리오 A·B·C (8개)
node --test scripts/agent-office/test/download-preflight.test.mjs # 사전 점검 규칙 (18개)
node --test scripts/agent-office/test/real-form-compatibility.test.mjs # 실제 양식 호환성 (15개)
```

실제 기관 양식 10종+2종 전수 결과는 [실제 기관 양식 검증](real-forms-verification.md)에 따로 정리했습니다.

| 항목 | A 주민 교육 추진계획서 | B 프로그램 운영계획서 | C 사업 결과보고서 |
| --- | --- | --- | --- |
| 사용한 양식 | 연습 양식 `plan-practice-form.hwpx` | 같은 양식(내용만 교체) | 결과보고서 양식(글자) + `report-base.hwpx` |
| 인식한 칸 | 25 | 25 | 7 |
| 자유 텍스트 배치 | 17칸 (모두 라벨 일치 `score 1`) | 13칸 (모두 `score 1`) | 3칸 |
| 사전 점검 | 막는 항목 0 · 예산 총액=비목 합 일치 | 예산 불일치(차액 200,000원) **권장** 1건, 다운로드 막지 않음 | 결과보고 불완전·출석 미입력 **직접 확인/권장**, 파일 없으면 막음 |
| `.hwpx` 패치 | 채운 칸 17 · 그대로 둔 칸 0 · 못 찾은 값 0 | 채운 칸 13 · 못 찾은 값 0 | 결과보고 .hwpx 생성(참석 12명 + 미입력 1회차 문장) |
| 서식 보존 | `header.xml` 바이트 동일 · 표·칸·문단 수 동일 | 같음 | 결과보고 바탕 서식 사용 |
| 수정값 유지 | 3단계에서 고친 값이 다시 읽은 문서에 남음 | 같음 | 출석 0명 vs 미입력 구분 |

추가로 확인한 것:

- **엉뚱한 칸에 붙은 값**: 연습 양식에 없는 `출석 인원: 0명`을 붙여넣으면 자유 배치가 `참여 인원` 칸에 붙입니다.
  사전 점검이 이것을 **형식 오류(막음)**로 잡아 조용히 지나가지 않습니다. 칸에서 고치면 다른 칸 값은 그대로입니다.
- **한 칸에 값 두 줄**: 형식 검사보다 먼저 “이 칸에는 하나만” 으로 막습니다.
- **금액 내역**: `총 4,800만원 (국비 3,360, 군비 960)`처럼 내역이 함께 적힌 값은 오류로 보지 않습니다
  (양식 칸에 글로 들어가는 값). 단위 없이 숫자만 있으면 “무엇인지 알기 어렵다”고 권합니다.
- **원본 값 보존**: 원본에 이미 값이 있는 칸은 덮어쓰지 않고 `직접 확인`에 “그대로 둡니다”로 표시합니다.
- **다운로드 실패**: zip이 아님·본문 없음·메모리 부족을 각각 쉬운 한국어 이유와 다음 할 일로 바꿉니다.

브라우저 확인(헤드리스 Chromium, 390×844 · 1440×1000, 로컬 빌드): 긴 문장 입력 시 높이 42px → 354px(모바일),
39px → 123px(데스크톱)로 늘어나고 안쪽 스크롤·가로 넘침 0, 커서가 보이는 상태 유지. 새로고침 후 값·수정값 유지,
두 번 눌러 내려받은 `.hwpx`에 긴 문장·수정 날짜·빈칸에서 채운 값이 모두 들어 있음을 확인했습니다. 콘솔 오류 0건.

## 4. 사람이 반드시 확인할 항목 (자동 검증 불가)

- [ ] 받은 `.hwpx`가 한컴오피스에서 열린다(경고·복구 창 없이).
- [ ] 글꼴·글자 크기·표 테두리·병합 칸이 원본과 같다.
- [ ] 쪽 나눔·여백·인쇄 미리보기가 원본과 같다(특히 표가 많은 양식).
- [ ] 값이 들어간 칸의 줄바꿈·정렬이 어색하지 않다(여러 줄 값 포함).
- [ ] 원본에 이미 있던 값이 지워지거나 바뀌지 않았다.
- [ ] 그림·도장·직인 이미지가 그대로 남아 있다.
- [ ] 긴 문장을 넣었을 때 그 칸이 몇 줄로 늘어나는지, 표가 아래로 밀리지 않는지 눈으로 본다.
- [ ] 제출 기관이 요구하는 파일명 규칙에 맞게 저장했다.

## 5. 이번에 고친 것 (다음 측정 때 다시 볼 지점)

1. 검토 표 입력칸이 한 줄 높이에 머물러 긴 문장의 나머지가 가려지던 문제 — 내용만큼 늘어나는 입력칸으로 바꿈.
2. 표에 값이 있는 칸만 보여 빈칸·필수 빈칸을 알 수 없던 문제 — 3단계에 상태 표시와 ‘아직 비어 있는 칸’ 목록 추가.
3. 다운로드 전에 필수값·형식·미배치 글·예산 합계·출석을 한 번에 볼 수 없던 문제 — 사전 점검 패널 추가
   (막는 항목이 있으면 한 번 안내하고, 두 번째 누르면 그대로 내려받음).
4. 실패 이유가 영어 예외 메시지로 나오던 문제 — 쉬운 한국어 이유와 다음 할 일로 바꿈.

측정할 때는 1~4가 실제로 시간을 줄였는지(지표 2·3·4)와, 사전 점검의 “권장/직접 확인”이 너무 잦아
귀찮게 느껴지지 않는지(지표 7)를 봅니다.
