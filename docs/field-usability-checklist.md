# 실무 사용성 측정표 — 양식 채우기 (Planning Copilot)

이 문서는 **사람이 직접 재는** 사용성 측정표입니다. 실무자(사용자) 한 사람이 실제 기관 양식 3종으로
`샘플 양식 채우기` 화면을 한 번씩 끝까지 써 보고, 아래 표의 빈칸을 채웁니다.
기계가 확인할 수 있는 값(칸 인식 수, 채운 칸 수, 다운로드 성공, 서식 훼손 여부)은 4장에 따로 적었으니
**2장 빈칸에는 사람이 느끼고 판단한 것만** 적습니다. 두 표를 섞으면 "자동 검증을 사람이 쓴 것처럼" 보이므로 섞지 않습니다.

측정 대상 양식(원본은 `work/real-forms/`, 저장소에 커밋하지 않음):

| 번호 | 양식 | 쓰임 |
| --- | --- | --- |
| 양식 1 | 2027년 양양군 시군역량강화사업 예비계획서 | 군에 내는 사업 계획서 |
| 양식 2 | 내가그린양양 강사료 청구서 | 재단에 내는 강사료 청구 |
| 양식 3 | 내가Green양양 위촉계약서 서식1 | 강사 위촉 계약 |

## 1. 측정 전 준비

1. 개인정보(주민등록번호·연락처·성명)를 지운 사본으로 측정합니다. 원본 파일은 고치지 않습니다.
2. 측정 전에 지금까지 쓰던 방식의 시간을 먼저 잽니다(같은 양식을 한글에서 열어 채우고 저장하는 데 걸린 시간).
3. 측정 중에는 화면을 끄지 말고, 막힌 지점이 나오면 그 자리에서 8번 칸에 적습니다.
4. 측정 후 받은 `.hwpx`를 한컴오피스에서 직접 열어 5장 항목을 확인합니다.

## 3. 같은 기준으로 세는 법

- **기존 방식 작업시간**: 양식을 열어 값을 다 채우고 저장·제출본을 만들 때까지. 파일 찾는 시간은 제외.
- **Planning Copilot 작업시간**: ① 양식 불러오기 시작부터 ④ `.hwpx` 내려받기 완료까지. 한글에서 최종 손보는 시간은 따로 적습니다.
- **자동 입력 성공 항목 수**: 내가 고치지 않아도 맞게 들어간 칸 수.
- **수동 수정 항목 수**: 값은 들어갔지만 내가 고친 칸 + 값이 안 들어가 내가 채운 칸.
- **누락·오기입 건수**: 값이 빠진 칸, 다른 칸에 들어간 값, 숫자·날짜가 틀리게 들어간 건을 합쳐서 셉니다(0이면 0이라고 적습니다).
- **다운로드 성공 여부**: 성공 / 실패(이유). 실패면 4장의 자동 검증 결과와 함께 봅니다.
- **사용자가 막힌 단계**: ① 양식 불러오기 / ② 자료 붙여넣기 / ③ 검토·수정 / ④ 다운로드 / 없음.
- **다음에도 사용하고 싶은지**: 예 / 조건부(이유) / 아니오(이유).

## 4. 자동 검증으로 확인된 수치 (사람 측정 아님 · 2026-11-15, 커밋 `feat/pr14-field-accuracy-ux`)

아래 값은 브라우저 없이 앱의 같은 코드 경로(양식 읽기 → 칸 인식 → 자유 텍스트 배치 → HWPX 패치)를 그대로 돌려
기계로 확인한 결과입니다. 사람의 사용성 판단·작업시간이 아닙니다.

| 항목 | 양식 1 예비계획서 | 양식 2 청구서 | 양식 3 계약서 |
| --- | --- | --- | --- |
| 문서 읽기(섹션/표) | 섹션 51 · 표 57 | 섹션 0 · 표 2 | 섹션 25 · 표 1 |
| 인식한 칸(빈 칸) | 520 (97) | 4 (1) | 0 (0) |
| 자유 텍스트 → 칸 배치 | 14줄 → 값 13개 | 3줄 → 값 3개 | 값 0개 |
| 실제로 채운 칸 | 4 (지정서 기관명·대표자·소재지·지정기간) | 1 (입금계좌) | 0 |
| 원본 값이 있어 그대로 둔 칸 | 19 | 2 | 0 |
| 자리를 못 찾은 값 | 0 | 0 | 0 |
| `.hwpx` 다시 읽기(kordoc) | 성공(44,260자) | 성공(599자) | 성공(2,619자) |
| `kordoc validate` | 원본·결과 모두 실패 | 원본·결과 모두 통과 | 원본·결과 모두 통과 |
| 표/칸 수 보존 | 64→64 / 1,223→1,223 | 2→2 / 12→12 | 1→1 / 2→2 |
| header.xml(서식 정의) 바이트 | 동일 | 동일 | 동일 |

- 양식 1의 `kordoc validate` 실패는 **원본 파일 결함**입니다. `Contents/content.hpf`가 `E:\...\27년 비전&미션.png` 같은
  로컬 경로 이미지를 참조하고 있습니다. 원본과 결과가 똑같이 실패하므로 이번 패치가 만든 문제는 아니지만,
  한컴오피스에서 열었을 때 그림이 빠질 수 있으니 **수동 확인 대상**입니다.
- 양식 3(계약서)은 서명 블록 한 칸에 `성 명 :`·`생년월일 :`·`주 소`가 함께 들어 있는 형태라 앱이 넣을 빈칸을 찾지 못합니다(0칸).
  이미 개인정보로 채워진 계약서 사본이어서 덮어쓰지 않은 것이 맞지만, **서명란 자동 채우기는 아직 안 되는 영역**으로 남깁니다.

## 5. 사람이 반드시 확인할 항목 (자동 검증 불가)

- [ ] 받은 `.hwpx`가 한컴오피스에서 열린다(경고·복구 창 없이).
- [ ] 글꼴·글자 크기·표 테두리·병합 칸이 원본과 같다.
- [ ] 쪽 나눔·여백·인쇄 미리보기가 원본과 같다(특히 양식 1처럼 표가 많은 문서).
- [ ] 값이 들어간 칸의 줄바꿈·정렬이 어색하지 않다(여러 줄 값 포함).
- [ ] 원본에 이미 있던 값이 지워지거나 바뀌지 않았다.
- [ ] 그림·도장·직인 이미지가 그대로 남아 있다(양식 1은 원본 결함 때문에 특히 확인).
- [ ] 제출 기관이 요구하는 파일명 규칙에 맞게 저장했다.

## 6. 이번 자동 검증에서 고친 것 (다음 측정 때 다시 볼 지점)

1. 레이아웃 칸 안에 든 표(중첩 표)를 채우기 대상에서 건너뛰던 문제 — 양식 1의 지정서 표가 여기에 해당합니다.
2. 청구서 첫 줄(`소속 및 직위 | 값`)을 표 머리글로 오인해 첫 항목을 잃던 문제 — 양식 2 칸 인식 3개 → 4개.
3. `1. 기관명 :`처럼 항목 번호가 붙은 라벨을 매칭하지 못하던 문제 — 양식 1 지정서 4칸 채우기 가능해짐.
4. 칸 글자 안의 줄바꿈·탭 요소(`<hp:lineBreak/>`)를 글자로 세어 라벨 비교가 어긋나던 문제 — 양식 1.
5. 원본 값을 그대로 둔 칸을 "자리를 못 찾은 값"으로 잘못 보고하던 문제 — 안내 문구가 틀리게 나오던 부분.

## 7. 측정 결과 해석

- 자동 입력 성공 항목 수가 많아도 **수동 수정 항목 수**가 많으면 실무 시간은 줄지 않습니다. 두 값을 같이 봅니다.
- 누락·오기입이 1건이라도 있으면 그 양식은 "다음에도 사용" 판정 전에 원인(칸 인식/배치/서식)을 적어 둡니다.
- 측정표는 양식 유형별로 한 줄씩만 쌓아도 어느 양식에서 시간이 줄고 어디서 막히는지 드러납니다.
